# Runtime foundation audit — 2026-09-08

This is a source-grounded inventory of the existing Rust daemon, with bounded local regression validation. It is not a claim that arbitrary workflows resume after a crash. No paid model calls, external messages, or third-party memory installation were used.

## Persistence and execution

- Agent task lists already use the agent ID under `.animaos-swarm/agent-tasks`. `hosts/rust-daemon/src/tools/todo.rs`, `agent_todo_path` and `write_agent_todos`, isolate ownership, serialize writes, compare revisions for owner edits, and atomically replace the file. Task creation does not enable scheduling.
- `hosts/rust-daemon/src/agent_runs.rs`, `run_serialized` and `run_locked`, provide daemon-wide admission, per-agent serialization, a persisted Running snapshot before execution, and serialized final snapshot commits. Peer/delegated runs fail fast when the target is busy. Detached worker execution survives the requesting HTTP future being dropped; it does not survive process termination.
- `hosts/rust-daemon/src/state.rs`, `restore_agent_runtime`, marks restored Running agents failed with `daemon restarted before task completed`. Saved messages, configuration, and results are durable state, not automatic continuation. Core checkpoint/recovery abstractions must not be advertised as a fully wired daemon workflow engine.
- `hosts/rust-daemon/src/schedules.rs`, `claim_due` and `reconcile_interrupted`, persist claims before running. Unresolved occurrences without an active worker are disabled with `schedule_run_interrupted`, requiring review rather than automatic side-effect replay. Reconciliation persistence failure restores the previous state for a later tick. Existing tests cover orphaned claims after storage recovery and parallel due agents.

## Communication and authority

- `packages/core-rust/crates/anima-core/src/communication.rs` already enforces sender lineage, cycle rejection, three hops, and a shared twelve-request budget across route clones/broadcast branches.
- `hosts/rust-daemon/src/agent_runs.rs`, `send_peer` and `run_locked`, check each originating agent's configured tools before peer admission. `hosts/rust-daemon/src/tools.rs`, `execute_tool`, rechecks originating authority before actual tool execution.
- Manager delegation requires a lead and a different non-manager target. It rejects targets with tools outside the manager's authority, removes delegation and peer communication from delegated execution, and rechecks current parent tool authority. These protections already existed; this delivery does not claim them as new fixes.
- These limits constrain communication fan-out and concurrency; they are not a durable, owner-visible aggregate cost budget across a workplace goal.

## Memory wiring and bounded correction

The daemon uses `anima_memory::MemoryManager`, shared behind a Tokio write lock, with JSON/SQLite/Postgres snapshot persistence in `hosts/rust-daemon/src/memory_store.rs`. `hosts/rust-daemon/src/app/persistence.rs`, `configure_memory_store`, restores the manager at startup. `hosts/rust-daemon/src/tools/memory.rs` exposes agent-scoped search, add, and recent memory. `hosts/rust-daemon/src/memory_embeddings.rs` provides rebuildable vector indexing with local and separately configured providers. This is real first-party memory wiring, but not the newer core `MemoryPort` authority/revision protocol.

Concrete defect: `memory_add` and automatic task-result capture changed the shared manager before attempting persistence. A failed save returned/logged an error while leaving the rejected memory searchable; a later successful snapshot could silently commit it. The shared `MemoryMutation` guard now restores the prior manager snapshot while retaining the same write lock on persistence failure, early validation return, or cancellation. The correction covers the tool, task-result capture, evaluator, swarm relationship recording, and all mutating owner memory routes. Swarm evidence indexing now stops after a failed save; other corrected paths already indexed only after success.

Regression coverage exercises an actual JSON write failure using a directory as the destination, then checks that the rejected memory is neither visible nor present in a later successful saved snapshot. Additional coverage verifies graph records and text search are restored after failed deletion, successful deletion remains committed, and early-return rollback preserves the prior snapshot. The task-result regression failed before the fix with visible size 1 instead of 0 (`target/runtime-memory-red.log`). Integrated validation outcomes are recorded by the coordinating task after all changes are combined.

Memory JSON snapshots now follow the already-atomic control-plane pattern: write to a temporary file using the existing `atomicwrites` dependency, sync file contents and replace the destination; the library itself syncs parent directories on Unix. A failure-injection regression proves a partial writer error preserves the previous valid on-disk snapshot and cleans up the temporary file. It failed before correction because the destination contained only `partial` bytes. This test covers failed writes before replacement; it does not simulate power loss.

Post-replacement errors are distinguished from rejected writes. `atomicwrites` can return an internal error after its rename succeeds (for example, parent-directory sync failure). The memory writer checks destination bytes against the intended snapshot. A confirmed match returns an explicit `snapshot committed; durability uncertain` error and retains the new canonical memory instead of rolling it back. Regression coverage injects an error after real atomic replacement, verifies memory matches disk, and checks the uncertainty remains visible to the caller. The pre-replacement failure regression continues to verify rollback protection.

Residual persistence work: full-memory snapshots have scaling costs. If the destination cannot be read after an internal write error, commit state remains ambiguous; the original error and rollback behavior remain, requiring recovery/reconciliation. A remote database acknowledgement error can also occur after commit. Derived embedding updates are skipped when durability is uncertain and may require rebuilding. These are not cross-store exactly-once transactions.

Keep memory semantics first-party. Evaluate correction lineage, deletion/forgetting, restart recovery, revision conflicts, tenant visibility, and retrieval quality before adding infrastructure. Optional vector/database adapters should answer a measured capacity or latency problem; installing Mem0, Graphiti, Qdrant, or another package alone would not resolve daemon transaction semantics. No package installation is part of this delivery.

## Native work tools and extensions

`hosts/rust-daemon/src/tools.rs`, `ToolRegistry::new`, registers file read/list/search/write/edit/multi-edit, shell execution, managed background processes, memory, tasks, communication, web fetch, Exa search, calendar, and mail operations. Tool registration is distinct from an agent's configured authority and from external credential readiness. Exa search is present in current source and requires its configuration; older notes saying no search tool exists are outdated.

Coding can use native file/process primitives inside the configured workspace. Dedicated office document rendering/verification, browser automation, camera, and voice engines are not established by this registry. A generic file writer or shell is not a first-class document production engine. Mail draft tools must not be described as permission-free sending. Extension documentation should use the existing portable core capability manifest/invocation boundary, while acknowledging that daemon handlers are statically registered rather than dynamically loaded plugins.

## Startup acceptance scenario

Final combined validation: `bun x nx run rust-daemon:test --skipNxCache` passed 997 checks with 5 ignored. Web/SDK full suites passed 336/37 tests and both builds/typechecks. The final capabilities adjustment passed its focused 4-test suite and another web build/typecheck. Independent review's postcommit finding was fixed and re-reviewed. A disposable live daemon restart preserved agent ID, task revision/content, and private memory ID/content; interrupted autonomous work and power-loss simulation were not part of that live check. No ignored or Unix-only coverage is claimed as executed on Windows.

Start the daemon with persistent stores and a configured workspace. Create an agent-owned task without enabling a schedule, write a permitted file, and verify the task/file after restart. Explicitly enable a schedule only after checking its agent authority. Interrupt an in-flight run, restart, and confirm that its failed/interrupted state is visible and an unresolved schedule is disabled for review. Confirm memory survives a successful save and rejected memory does not become visible after a failed save. Confirm a restricted agent cannot enlist a peer or delegate to perform an ungranted tool action. These are acceptance steps, not claims that this entire scenario has been executed live in this audit.
